# ByteBar Library — preview build (staging only)

The owned library front door (SPEC §4), implementing the approved Home v2
design + the approved course screen. Built 2026-11-11. **Not announced,
not linked from any live page, `noindex` on every page.**

## Pages
- `index.html` — library home: header-zone search ("Find your topic"),
  Continue Learning rail (progress-driven), goal picker, vendor filter
  chips, cover grid for all 13 ByteBar books, Nursing shelf (warm palette
  as a category cue), simulator band.
- `course.html?book=<slug>` — course page: progress header, chapter rows
  with watched / up-next / in-production states, Final Exam capstone
  routing to the simulator. Security+ is fully populated from the real
  TOC; every other ByteBar book renders from the same data.
- `watch.html?book=<slug>&ch=<n>` — chapter player: video (or a
  "being built" poster for unbanked chapters), resume-position saving,
  mark-watched, prev/next, the book's chapter list, capstone card.

## Data & plumbing
- `data.js` — generated by `build_catalog.py` from the deployed playlist
  snapshot (`hidden_files/library-refresh-2026-11-10/book_playlists.json`,
  2026-11-10 — the same source the live library pages use). Re-run the
  generator to refresh; do not hand-edit `data.js`.
- `streams.js` — book → chapter → stream map. Starts empty except
  Security+ Start Here (the one banked Library Edition unit), which
  points at `media/secplus/00-start-here.mp4` for staging playback.
  Chapters with no entry render "In production" everywhere.
- `config.js` — the simulator's Supabase project (URL + public anon key,
  same as the sim ships) + empty Bunny slots + the signing-function name.
- `library.js` — auth (magic link, PKCE code exchange, mirroring the
  sim's `backend.js.html` pattern), progress store (localStorage +
  Supabase sync), signed-URL stub (`BB.resolveStream`).
- `PROGRESS-SCHEMA.sql` — the `library_progress` table + RLS policies,
  **for review only — NOT executed** against the production project.
  Until it is applied, progress sync fails soft to localStorage.
- `media/` — staging-only copy of the banked Start Here video + poster.
  Production rule (SPEC §4.2) stands: catalog video bytes never live in
  the repo — they move to Bunny when the account exists, and `streams.js`
  is the only file that changes.

## Deploy (preview only)
Upload this folder's contents to `ByteBarHQ/bytebar-landing` at
`library-preview/` via GitHub's web uploader (the same route the sim
preview used) → https://bytebarhq.com/library-preview/
Do NOT touch the repo root `index.html` or `library/` — those are the
live homepage and live library pages.

  the "~" totals are the approved mock's estimates; measured Library
